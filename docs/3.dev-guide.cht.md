## 1 開發前準備

### 1-1 你需要哪些工具

- Windows + PowerShell
- Node.js（LTS 版）
- Wrangler（Cloudflare CLI）

---

### 1-2 這份教學假設

- 你已經看過建置教學，知道如何在 Cloudflare 建好 Pages / KV / D1 / Turnstile
- 你已經能成功部署一次 PicoTag，並能正常使用網站功能。

## 2 修改檔案的位置與專案結構

> 本文件以「從 GitHub Releases 下載 ZIP 並解壓縮」為主流程：你只要在解壓縮後的 `PicoTag` 資料夾內修改檔案即可。

### 2-1 下載 ZIP 並解壓縮到本機

1. 到 GitHub 專案頁的 **Releases** 下載你要的版本 ZIP（例如 `PicoTag_v1.0.2.zip`）  
2. 解壓縮到本機資料夾，例如：`C:\PicoTag`

> 小提醒：解壓縮後請確認 `C:\PicoTag` 這一層就看得到 `index.html`（不要多一層資料夾）。

---

### 2-2 你主要會改到哪些檔案

PicoTag 主要是「靜態網站檔案」，常見位置：

- `index.html`：Tag 查詢頁（一般使用者掃 QR Code 會看到的頁面）
- `admin/new`：建立 Tag 相關頁面（依你的版本結構可能不同）
- `admin/`：後台頁面（system / records / site / reference…）
- `assets/`：JS / CSS / i18n / version.json 等資源
  - `assets/js/`：前端主要邏輯
  - `assets/css/`：樣式
  - `i18n/`：多國語言 JSON

> 你可以依需求修改程式碼後，再照下一個章節重新部署上線。

## 3 重新部署到 Cloudflare Pages（讓修改上線）
每次改完檔案想上線，請照同一條指令重新部署：

1. 在 PowerShell 切換到你解壓縮後的 PicoTag 資料夾
2. 用 dir 指令確認目前資料夾內看得到 index.html  
   - 如果看不到 `index.html`，表示你還在外層，請再 `cd` 進去正確那一層
3. 執行部署指令（會把目前資料夾內的檔案重新上傳到 Cloudflare Pages）

```powershell
wrangler pages deploy . --project-name picotag-demo
```

> 小提醒：`picotag-demo` 請替換成你自己的 Pages 專案名稱。

> 重要提醒：
> 如果你有在 Cloudflare Pages 後台修改 **Variables / Bindings**，必須要「重新部署」後，線上環境才會真的使用到新設定。

部署成功後，重新整理你的網站頁面，確認內容是否更新。
